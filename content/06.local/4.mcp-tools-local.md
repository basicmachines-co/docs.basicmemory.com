MCP tools are the same in Cloud and Local. In local mode, they operate on folders on your machine.

## Use tools in local mode

Once your MCP client runs the local server (see [Local install](/local/local-install#connect-your-mcp-client)), tools read and write your local project folders — unless you've routed a project through cloud with [per-project routing](/cloud/routing).

## Common tools

- `search_notes` to find notes (keyword, semantic, and hybrid search)
- `read_note` to load a note
- `write_note` to create or update a note
- `edit_note` to append or replace sections
- `schema_validate`, `schema_infer`, `schema_diff` for schema workflows
- `build_context` for graph traversal via [memory:// URLs](/concepts/memory-urls)

Most tools default to `output_format="text"` (human-readable) and also accept `"json"` (machine-readable); `build_context` defaults to `"json"` — see the [MCP Tools Reference](/reference/mcp-tools-reference) for per-tool defaults.

## POSIX read tools

Since v0.24, the server also exposes six read-only tools modeled on shell commands: `ls`, `find`, `grep`, `cat`, `tail`, and `man`. Your local projects act as mount points: `ls(path="/")` lists them, and a path that starts with a project name reads from that project.

```python
ls(path="/")                                         # list projects
find(path="research", meta=["status=active"])        # notes by frontmatter
grep(pattern="retry", project="main", context_lines=3)
cat(identifier="research/specs/auth.md", section="Decisions")
```

To hide them, set `enable_posix_tools` to `false` in `~/.basic-memory/config.json` (or `BASIC_MEMORY_ENABLE_POSIX_TOOLS=false`) and restart your MCP client.

## Which project a call uses

A call without `project` uses your `default_project`. There is no per-session "active project" to switch, so pass `project` on each call that targets another project. If the server was started with `BASIC_MEMORY_MCP_PROJECT`, every call is constrained to that project.

The POSIX tools are stricter: with more than one project, an unqualified path (or a `grep` / `tail` call without `project`) is refused rather than defaulted, so qualify the path (`main/notes/x.md`) or pass `project`.

## Semantic search

Semantic search is always on in v0.24; the old `semantic_search_enabled` setting is ignored. The first run downloads a small local embedding model and builds vectors for your notes. If the vector runtime cannot load on your Python build (for example python.org Python on macOS), search falls back to keyword-only. See [Semantic Search](/concepts/semantic-search).

## Example

```python
search_notes(query="architecture", project="main")
```

::tip
Each tool has a manual page built in. Ask your assistant to read `memory://man`, or run `bm man search-notes` in a terminal.
::
