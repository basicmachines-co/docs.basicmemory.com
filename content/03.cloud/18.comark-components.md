---
title: Comark Components
description: Every Basic Memory Comark component, with its Markdown source, how it renders, every attribute it accepts, and a link to try it in the playground.
---

Basic Memory Cloud renders these components in Notes, the [Wiki](/cloud/wiki), and [shared notes](/cloud/shared-notes). Each one is written as Markdown: a `::bm-` directive with attributes in braces, a body, and a closing `::`. Everywhere else, in a local editor, on GitHub, or in a raw `bm_read`, the same note reads as plain Markdown, so your AI writes and reads these as text.

Each example below shows its source, how it renders, and every attribute it accepts. **Open in playground** loads it in the [Comark playground](https://app.basicmemory.com/playground){target="_blank"}, where you can edit the source and switch between the rendered view and the plain text an agent reads. See [Live Notes](/cloud/live-notes) for how components and live views fit into a note.

::tip
Your AI can learn every component and its attributes from the `memory-comark` [agent skill](/integrations/skills), or from the `comark(7)` manual page (`bm man comark`, or `memory://man/comark(7)` over MCP).
::

---

## Content and layout

### Frame

`bm-frame`: A framed claim or section with an optional theme-derived visual.

```markdown
::bm-frame{title="Release 1.0" description="One Markdown source for Notes, Wiki, and export." variant="emphasized" visual="dither-mesh"}
## Ready for the final mile

The release is healthy, the migration is ahead of plan, and two decisions remain.
::
```

::

[Open in playground ↗](https://app.basicmemory.com/playground?example=bm-frame){target="_blank"}

#### Frame attributes

**Body:** Any Markdown.

| Attribute | Accepts | Default | Description |
| --- | --- | --- | --- |
| `title` | Text |  | Label drawn in the frame header. |
| `description` | Text |  | Lead line under the title. |
| `variant` | `default`, `subtle`, `emphasized` | `default` | Frame weight. |
| `density` | `comfortable`, `compact` | `comfortable` | Spacing inside the frame. |
| `visual` | `none`, `dither`, `dither-mesh`, `dither-scan` | `none` | Static, theme-derived pattern behind the frame. |

### ASCII

`bm-ascii`: A local image redrawn as a character field, with bounded motion.

```markdown
::bm-ascii{title="Geometric wave" preset="paper" detail="high" contrast="edge" polarity="dark" motion="wave"}
![Layered dark blue waves curling around a pale circular moon](/playground/media/ascii-wave.svg)
::
```

::theme-image{light="/screenshots/comark/comark-bm-ascii-light.png" dark="/screenshots/comark/comark-bm-ascii-dark.png" alt="The bm-ascii example rendered"}
::

[Open in playground ↗](https://app.basicmemory.com/playground?example=bm-ascii){target="_blank"}

#### ASCII attributes

**Body:** One Markdown image of a project file, with alt text. `rain` and `glitch` need no image.

| Attribute | Accepts | Default | Description |
| --- | --- | --- | --- |
| `title` | Text |  | Label drawn in the frame header. |
| `caption` | Text |  | Short line under the figure that says what it shows. |
| `preset` | `crisp`, `paper` | `crisp` | Character set and texture. |
| `detail` | `low`, `medium`, `high` | `medium` | How many characters sample the image. |
| `contrast` | `soft`, `edge` | `edge` | Soft tones or hard edges. |
| `polarity` | `dark`, `light` | `dark` | Whether dark or light areas of the image draw characters. |
| `motion` | `none`, `drift`, `pulse`, `wave`, `rain`, `glitch` | `none` | Bounded animation. Motion stops when the viewer asks for reduced motion. |

### Live pipelines

`live-view`: Query pipelines run against a small sample project in your browser.

```markdown
# Live pipelines

Each view below names a component and pipes rows into it, read left to right:
a source, then `where`, `group`, `count` or `sum`, `fields`, `sort`, and `limit`.
Here they run against a small sample project in your browser; Cloud runs them
against the project's indexed metadata.

::bm-bars{title="Open decisions by owner" query="notes | where type == decision and status != done | group owner | sort count desc"}
::

The bars above count every decision that is not done, including the one with no
status at all. Below, the same rows feed a ranked list and a points total.

::bm-rank{title="Points by owner" query="notes | group owner | sum points | sort sum desc | limit 5"}
::

::bm-stat{label="Active objectives" query="notes | where type == objective and status == open | count"}
::

::bm-table{title="Infra work due soon" query="notes | where tags contains infra and due < 2026-10-15 | fields title, owner, due | sort due"}
::

Activity reads the product feed. `daily` counts every event per day, so a busy
day is never cut off at a row limit.

::bm-activity{title="Edits per day" query="activity 30d | daily"}
::

::bm-timeline{title="Recent edits" query="activity 7d"}
::

Search ranks notes by a phrase. Quote the phrase with single quotes, because the
`query` attribute is itself double-quoted. Filters after a search compare with `==`.

::bm-rank{title="Search: postgres" query="search 'postgres' | limit 5"}
::

::bm-table{title="Decisions about the queue" query="search 'queue rewrite' hybrid | where type == decision | limit 5"}
::

A live chart keeps its last frozen snapshot as its body. Readers see live rows;
when live data cannot load, the snapshot shows instead. In the editor, **Freeze
snapshot** rewrites this body from the current rows.

::bm-funnel{title="Decision status" query="notes | where type == decision | group status | sort count desc"}
- open: 2
- done: 1
::

A query the component cannot draw fails inside its own frame in preview, with a
coded problem and a fix. Try changing a query above to `notes | fields title`.
```
