**Live notes** show the work inside the note. Put a KPI, a Gantt chart, a comparison, or a task board in any note: the data sits in the note as ordinary Markdown lists and tables, and Basic Memory draws the figure. A **live view** goes further and runs a query over your project each time you open it, so a chart of open tasks is always the current one.

::theme-image{light="/screenshots/cloud-app/live-note-board-light.png" dark="/screenshots/cloud-app/live-note-board-dark.png" alt="A live note with a tasks-by-status chart, a task board, and a live table of open tasks"}
::

Basic Memory supports [Comark](https://comark.dev/), an open Markdown syntax for components. Basic Memory Cloud renders the components in Notes, the [Wiki](/cloud/wiki), and [shared notes](/cloud/shared-notes). Everywhere else, in a local editor, on GitHub, or in a raw `bm_read`, the note still reads as plain Markdown.

## Write a component

A component is a `::bm-` directive with attributes in braces, a Markdown body, and a closing `::`. This is part of a real note's source:

```markdown
::bm-kpi{title="Customers migrated" value="26" label="of 40 in cohort one" hint="65%" data="0,3,7,12,16,21,26"}
::

::bm-funnel{title="Beta switch funnel"}
- Saw the new plans: 112
- Opened the usage chart: 84
- **Set a spending limit: 57**
- Switched plans: 31
::
```

And this is what Basic Memory draws from it:

::theme-image{light="/screenshots/cloud-app/comark-kpi-light.png" dark="/screenshots/cloud-app/comark-kpi-dark.png" alt="The bm-kpi component rendered: 26 of 40 customers migrated, 65%, with a trend"}
::

::theme-image{light="/screenshots/cloud-app/comark-funnel-light.png" dark="/screenshots/cloud-app/comark-funnel-dark.png" alt="The bm-funnel component rendered: 112 saw the plans, 84 opened the usage chart, 57 set a spending limit, 31 switched"}
::

Bold a row (`**Set a spending limit: 57**`) to highlight it. Your AI writes components the same way you do, and reads them back as text, numbers included.

## Live views

Give a component a `query` and it becomes a read-only view over the project that contains it. The query is a pipeline, read left to right:

```markdown
::bm-bars{title="Tasks by status" query="notes | where type == task | group status"}
::

::bm-table{title="Open tasks" query="notes | where type == task and status != done | fields title, owner, due | sort due"}
::

::bm-activity{title="Edits per day" query="activity 30d | daily"}
::
```

| Part | What it does |
| --- | --- |
| **Sources** | `notes` (your notes' frontmatter), `search 'phrase'` or `search 'phrase' hybrid` (ranked results), `activity 7d` or `activity 30d` |
| **`where`** | Filters on a field: `==`, `!=`, `<`, `<=`, `>`, `>=`, `contains`, joined with `and` |
| **`group field`** | One row per value, with its count |
| **`count`**, **`sum field`** | One number over the filtered notes, or per group |
| **`fields a, b`** | Note rows with these columns |
| **`daily`** | One count per day, for `activity` |
| **`sort field [desc]`**, **`limit n`** | Order the rows; keep 1 to 50 |

Inside the double-quoted `query` attribute, quote phrases with single quotes: `query="search 'checksum conflict'"`.

Live views refresh when the project's notes change, at most once every 30 seconds per view. A live chart's Markdown body holds its last **snapshot**: readers see live rows, and if the query can't run, the snapshot shows with the reason. In the editor, **Freeze snapshot** rewrites the body from the current rows.

::note
A component that can't render, or a live view whose query fails, shows the problem inside that component. The rest of the note still renders, and a component never blocks a save.
::
