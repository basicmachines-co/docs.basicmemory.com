::note
This is a technical reference for developers and AI integrations. For a conceptual overview of what Basic Memory can do, see [What is Basic Memory](/start-here/what-is-basic-memory).
::

This page lists core Basic Memory MCP tools and their current parameters as of v0.24. For what changed in this release, see [What's New in v0.24](/whats-new/v0-24) and [Upgrade to v0.24](/whats-new/v0-24-upgrade).

::tip
Project resolution order is: constrained project env (`BASIC_MEMORY_MCP_PROJECT`) -> explicit `project` / `project_id` parameter -> `default_project` fallback. There is no session "active project": MCP requests carry no session state, so a call without `project` always uses the default project, locally and in the cloud. Pass `project` on every call that targets anything else.
::

::tip
**The manual is built in.** Every tool has a manual page served over MCP. `memory://man` is the index and `memory://man/<page>` is one page (for example `memory://man/search-notes(3)`). The `man` tool and `bm man <topic>` read the same pages. When a tool's description leaves a question open or a call fails, read its page.
::

### Common parameters

Most tools accept these optional parameters. They are **not** repeated in every table below.

| Parameter | Type | Default | Notes |
|---|---|---|---|
| `project` | string | resolved via fallback | Project name. Constrained project env → explicit parameter → `default_project` config |
| `project_id` | string | — | Project external UUID from `list_memory_projects`. Prefer this when the same project name exists in more than one workspace |
| `output_format` | `"text"` or `"json"` | `"text"` | Machine-readable JSON output. `build_context` defaults to `"json"`; most other tools default to `"text"` |

`workspace` is not a universal parameter. It appears on the note-writing tools (`write_note`, `edit_note`) and on the tools that create or delete cloud projects. For ordinary read, search, and schema calls, use `project` or `project_id`.

### Errors and refusals

Since v0.24, a refused or failed write is an MCP tool error (`isError: true`), never an ordinary result. This covers `write_note` (note already exists without `overwrite`, revision conflict, moved note, directory outside the project), `edit_note` (missing section, mismatched replacement count, concurrent-modification conflict, revision conflict), `delete_note`, and `move_note`. Nothing is written when a call is refused, so a client that checks `isError` can safely retry. In JSON mode, the error message is the same payload as before (for example `action: "conflict"`, `error: "NOTE_ALREADY_EXISTS"`).

`delete_note` still returns `false` (not an error) for a note that does not exist.

### Revision guards

`write_note` (with `overwrite=true`) and `edit_note` accept `expected_checksum`: the full `checksum` from a JSON `read_note`, `write_note`, or `edit_note` result. The write applies only while the note is still that revision. Otherwise nothing changes and the tool error is a revision conflict. A `write_note` conflict in JSON mode looks like this (`edit_note` returns the same fields with `operation` and `fileCreated` in place of `action`):

```json
{
  "title": "Meeting Notes",
  "permalink": "main/meetings/meeting-notes",
  "file_path": "meetings/Meeting Notes.md",
  "checksum": null,
  "action": "conflict",
  "error": "NOTE_REVISION_CONFLICT",
  "currentChecksum": "<the note's current checksum>"
}
```

`checksum` is `null` because nothing was written; retry against `currentChecksum` after re-reading the note. A guarded `append` or `prepend` on a note that no longer exists is a conflict, not an auto-create, and a checksum for a path no note owns is a conflict too, so a note deleted since you read it is never silently recreated. Without `expected_checksum`, `overwrite=true` still replaces unconditionally.

To refresh a stale checksum without reading the body, call `read_note(identifier=..., include_content=False)`. Text output shows only the first 8 characters of a checksum, so use JSON output when you plan to guard a write.

## Knowledge tools

### `write_note`

Create or update a markdown note.

| Parameter | Type | Required | Notes |
|---|---|---|---|
| `title` | string | Yes | Note title |
| `content` | string | Yes | Markdown body |
| `directory` | string | Yes | Relative folder path. Since v0.23.2, each segment resolves to a unique existing case-insensitive folder match |
| `tags` | list[string] or string | No | Comma-separated string accepted |
| `note_type` | string | No | Default `note`. Sets the `type` frontmatter field (e.g., `person`, `meeting`, `decision`) |
| `metadata` | object or JSON string | No | Extra frontmatter fields merged into the note's YAML header |
| `overwrite` | boolean | No | Default follows `write_note_overwrite_default` config (`false` unless changed). Pass `true` to replace an existing note; without it, writing to an existing path is a tool error |
| `expected_checksum` | string | No | With `overwrite=true`, replace the note only while it is still this revision. See [Revision guards](#revision-guards) |
| `workspace` | string | No | Cloud workspace to write into (name or tenant ID) |

The `note_type` parameter controls the `type` field in frontmatter, which is used for schema resolution and filtering. A `type:` in frontmatter inside `content` takes precedence over `note_type`. The `metadata` parameter accepts any key-value pairs that get written directly into the note's frontmatter — useful for custom fields like `status`, `priority`, or `due_date`. `write_note` does not add an H1 for you; include `# Title` in `content` if the note should open with one.

Aliases accepted for `directory`: `folder`, `dir`, and `path`.

**What `overwrite=true` does to frontmatter.** The body is replaced. Frontmatter keys this write sets (title, type, tags, metadata, or frontmatter in `content`) replace the old values; keys only the existing note has (custom fields) are kept. Existing frontmatter that cannot be parsed is discarded. To remove a key, use `edit_note` or edit the file.

**Similar existing notes.** When `write_note` creates a new note, it checks the semantic index for notes that look like it and, if any match closely, appends a "Similar existing notes" section asking whether you meant to write to one of those instead. Options are spelled out: merge into the existing note with `edit_note` and delete the new one, link the two with a relation, or ignore it. JSON output carries the same list as `similar_notes`. No scores are shown, notes the new note already links to are skipped, and nothing is changed on your behalf.

Results report the note's real checksum and end with `[Project: 'name']`, noting when no project was given and the default was used.

Folder casing resolution uses known indexed directories, so local and Cloud writes behave identically. Exact matches win; a unique case-insensitive match reuses the existing spelling; no match creates the folder as requested; and existing case-variant siblings keep exact-match behavior.

### `read_note`

Read note content by title/permalink/memory URL.

| Parameter | Type | Required | Notes |
|---|---|---|---|
| `identifier` | string | Yes | Title, permalink, or `memory://...` |
| `page` | integer | No | Pagination page number (for fallback search suggestions) |
| `page_size` | integer | No | Results per page |
| `include_frontmatter` | boolean | No | Default `false`. When `true`, includes YAML frontmatter in output |
| `start_line` | integer | No | First document line to read (1-based, inclusive). Lines count the full Markdown, frontmatter included, matching `cat` |
| `end_line` | integer | No | Last line to read (inclusive). Omit to read to the end |
| `include_content` | boolean | No | Default `true`. Set `false` to return only title, permalink, file path, full checksum, and `updated_at`, without the body. Cannot be combined with `start_line` / `end_line` |
| `review_mode` | `structured` or `raw` | No | Cloud only; default `structured`. Returns clean prose and typed review threads, or exact persisted CriticMarkup in `raw` mode |

With `start_line` or `end_line`, text output is numbered and JSON carries the range coordinates, `has_more`, and `next_start_line` / `next_end_line` for the next read. Reversed or invalid ranges fail; edits between calls can shift line numbers.

JSON output includes `checksum`, the revision that `write_note` and `edit_note` compare against when you pass `expected_checksum`. A note that does not exist returns `error: "NOTE_NOT_FOUND"` in JSON.

```text
read_note(identifier="specs/search-spec", start_line=120, end_line=180)
read_note(identifier="specs/search-spec", include_content=False, output_format="json")
```

On Cloud, structured JSON also returns `revision_checksum` and a `review` object containing summary counts and typed comment/suggestion items. Use that checksum for review decisions and for ordinary edits while review work is open. Raw mode is an inspection escape hatch; agents should not author or mutate CriticMarkup directly.

### `edit_note`

Edit an existing note incrementally.

| Parameter | Type | Required | Notes |
|---|---|---|---|
| `identifier` | string | Yes | Exact note identifier |
| `operation` | string | Yes | `append`, `prepend`, `find_replace`, `replace_section`, `insert_before_section`, `insert_after_section` |
| `content` | string | Yes | New content |
| `section` | string | Conditional | Required for `replace_section`, `insert_before_section`, `insert_after_section` |
| `find_text` | string | Conditional | Required for `find_replace` |
| `expected_replacements` | integer | No | Default `1` |
| `replace_subsections` | boolean | No | For `replace_section`; default `true` replaces nested subsections. Set `false` to preserve them |
| `metadata` | object | No | Merge frontmatter fields independently of the body operation; provided keys overwrite or add values |
| `expected_checksum` | string | No | Apply the edit only while the note is still this revision. See [Revision guards](#revision-guards) |
| `workspace` | string | No | Cloud workspace containing the note (name or tenant ID) |
| `expected_checksum` | string | No | Cloud reviewed notes require the checksum from structured `read_note`; stale or intersecting edits are rejected |

Aliases: `new_content`, `replacement`, `replace_with` for `content`; `section_heading`, `heading` for `section`; `find`, `old_text`, `old_content`, `search` for `find_text`.

::warning
**`replace_section` requires the exact heading.** Since v0.24, if the heading is not in the note, `replace_section` fails without writing instead of appending a duplicate section. A heading such as `## Open items #urgent` must be given in full. Use `append` to create a new section on purpose.
::

A failed or refused edit is an MCP tool error (`isError`), including a "modified concurrently" conflict when two clients edit one note. A refusal always comes from a write that rolled back, so a refused append is never in the note and is safe to retry.

`append` and `prepend` create the note if it does not exist (unless `expected_checksum` is set). `find_replace`, `replace_section`, and the `insert_*_section` operations require an existing note.

`replace_section` follows Markdown heading levels. By default, a selected section extends through the next heading of the same or higher level, so replacing an `##` section also replaces its nested `###` subsections. Set `replace_subsections=false` to stop at the next heading of any level and keep nested subsections.

`metadata` preserves unrelated frontmatter and the note body. It ignores `title` and `permalink`, which have dedicated handling, and does not support deleting keys. `metadata={"type": ...}` changes an existing note's type.

On Cloud, `edit_note` preserves active review markers byte-for-byte. If an edit would change an anchored review range, it fails with the blocking review ID; use `review_note` to resolve or decide that item first. `write_note(overwrite=true)` is a full replacement and may remove review state.

### `review_note` (Cloud)

Manage comments and suggestions on an existing Markdown note. Always begin with `read_note(review_mode="structured", output_format="json")`, and do not write CriticMarkup directly.

| Parameter | Type | Required | Notes |
|---|---|---|---|
| `identifier` | string | Yes | Exact title, permalink, file path, external ID, or `memory://` URL |
| `command` | `comment`, `suggest`, `reply`, `resolve`, `accept`, or `reject` | Yes | One review lifecycle action |
| `anchor` | object | Conditional | Required for `comment` and `suggest`. `exact` is a single-line prose selection; optional `prefix`, `suffix`, or one-based `occurrence` disambiguates repeated text |
| `body` | string | Conditional | Required for `comment` and `reply`; optional final reply when resolving a comment |
| `suggestion_kind` | `addition`, `deletion`, or `replacement` | Conditional | Required for `suggest` |
| `replacement` | string | Conditional | Required for addition and replacement suggestions; omit for deletion |
| `review_id` | string | Conditional | Required for `reply`, `resolve`, `accept`, and `reject`; obtain it from structured `read_note` or a prior mutation response |
| `expected_checksum` | string | Conditional | Required for `accept` and `reject`; optional stale-write guard for other commands |

`comment` and `suggest` create attributed review records and return their IDs. `reply` works on comments or suggestions. `resolve` closes a comment without changing its anchored prose and can include a final reply. `accept` applies a pending suggestion; `reject` keeps the original prose. Every mutation is atomic and returns the new `revision_checksum`.

```text
# Create a replacement suggestion
review_note(
  identifier="Launch plan",
  command="suggest",
  anchor={"exact": "Ship the beta on Friday."},
  suggestion_kind="replacement",
  replacement="Ship the beta after the security review."
)

# After a fresh structured read, accept it
review_note(
  identifier="Launch plan",
  command="accept",
  review_id="suggestion-id",
  expected_checksum="checksum-from-read-note"
)
```

See [Comments and Suggestions](/cloud/comments-and-suggestions) for the complete human-and-agent workflow.

### `move_note`

Move a note or directory.

| Parameter | Type | Required | Notes |
|---|---|---|---|
| `identifier` | string | Yes | Note or directory identifier |
| `destination_path` | string | Conditional | Target path. Mutually exclusive with `destination_folder`; parent folders receive v0.23.2 casing resolution |
| `destination_folder` | string | Conditional | Target folder — moves note into folder preserving filename. Mutually exclusive with `destination_path`; each segment can reuse a unique case-insensitive folder match |
| `is_directory` | boolean | No | Default `false`. Set to `true` to move an entire directory |

A failed or refused move is an MCP tool error. A move can rename a `.markdown` note to `.md`; other extension changes are refused. Directory moves move each note the same way `move_note` does for a single note, and apply the same cross-project guard.

Folder casing resolution applies to note destinations, not directory renames. The response reports the actual landing path after a case-corrected move. Case-only folder renames and merging already duplicated case variants remain separate operations.

### `delete_note`

Delete a note or directory.

| Parameter | Type | Required | Notes |
|---|---|---|---|
| `identifier` | string | Yes | Note or directory |
| `is_directory` | boolean | No | Set to `true` to delete an entire directory and its contents |

A refused delete (for example from a read-only API key, or a note with `locked: true` in its frontmatter) is an MCP tool error. A note that does not exist returns `false`. Deleting a note leaves relations that pointed at it in place as unresolved links, so recreating the target re-links them.

### `read_content`

Read a file's content by path or permalink. Text files return as plain text; PNG, JPEG, and WebP images are resized/optimized for display (other image formats, GIF included, return "Unsupported image format"); other binary files return base64-encoded (subject to size limits). Useful for non-markdown files like images, PDFs, or attachments. Only exact paths, permalinks, titles, and ids resolve; a miss is "Resource not found" rather than a fuzzy match to some other file.

| Parameter | Type | Required | Notes |
|---|---|---|---|
| `path` | string | Yes | File path, permalink, or `memory://...` URL. Aliases: `file_path`, `filepath`, `file` |

### `view_note`

Render a note as a formatted artifact for display in MCP clients. Returns the note content in a presentation-friendly format.

| Parameter | Type | Required | Notes |
|---|---|---|---|
| `identifier` | string | Yes | Note title, permalink, or `memory://...` URL |

### `open_basic_memory` (Cloud)

Open the interactive Pocketbook in a compatible client. Use this when the user wants to see, browse, navigate, or interact with Basic Memory visually. Use `read_note`, `search_notes`, or `list_directory` instead when the assistant only needs data for its answer.

The default workspace and project resolve automatically. Do not call `list_memory_projects` first unless the user asks for project metadata or wants a non-default location.

| Parameter | Type | Required | Notes |
|---|---|---|---|
| `view` | `notes`, `note`, `folders`, `search`, or `graph` | No | Default `notes`. Destination screen |
| `workspace` | string | No | Workspace slug, name, or tenant ID. Omit for the default |
| `project` | string | No | Project name or qualified workspace/project name. Omit for the default |
| `project_id` | string | No | Exact external project UUID. Takes precedence over `project` |
| `directory` | string | No | Initial folder for `notes`, `folders`, `note`, or `search` views |
| `identifier` | string | Conditional | Required for `view="note"`; optional for `view="graph"` to focus a note. Accepts a title, permalink, `memory://` URL, or exact note UUID |
| `query` | string | No | Initial query for `view="search"` only |
| `graph_mode` | `overview` or `full` | No | Default `overview`. Used only with `view="graph"` |
| `note_mode` | `view` or `edit` | No | Default `view`. Use `edit` to open a note directly in the editor; used only with `view="note"` |

Examples:

```text
open_basic_memory()
open_basic_memory(view="search", query="authentication")
open_basic_memory(view="folders", directory="research")
open_basic_memory(view="note", identifier="memory://main/plans/api", note_mode="edit")
open_basic_memory(view="graph", identifier="Architecture", graph_mode="full")
```

See [Pocketbook](/cloud/mcp-app) for the user workflow.

## Search and context tools

### `search_notes`

Main search tool with text, vector, and hybrid modes plus structured filters.

| Parameter | Type | Required | Notes |
|---|---|---|---|
| `query` | string | No | Search query. Optional for metadata-only searches. Supports `tag:` shorthand (e.g., `"tag:security"`) |
| `page` | integer | No | Default `1` |
| `page_size` | integer | No | Default `10` |
| `search_type` | string | No | Default `None` — resolves to `default_search_type` from config if set, otherwise `hybrid` (`text` on a local host where the vector runtime cannot load). Queries using `AND`, `OR`, or `NOT` run as `text`. Options: `text`, `title`, `permalink`, `vector`, `semantic`, `hybrid` |
| `note_types` | list[string] or string | No | Case-insensitive frontmatter `type` filter (e.g., `["person", "meeting"]`). Aliases: `note_type`, `types` |
| `entity_types` | list[string] or string | No | Knowledge graph result filter: `entity`, `observation`, `relation`. Alias: `entity_type` |
| `categories` | list[string] or string | No | Exact observation category filter (e.g., `["decision", "rule"]`). When provided without `entity_types`, results default to observations. |
| `after_date` | string | No | Date/time filter (ISO format) |
| `metadata_filters` | object or JSON string | No | Structured frontmatter filters. See [operators](#metadata-filter-operators) below |
| `tags` | list[string] or string | No | Tag filter shorthand; comma-separated string accepted |
| `status` | string | No | Status shorthand |
| `min_similarity` | float | No | Overrides global `semantic_min_similarity` threshold per query (vector and hybrid only) |
| `valid_at` | string | No | Date (`2026-07-28`) or RFC 3339 instant. Returns sources whose authored valid range contains it. Aliases: `as_of`, `valid_on` |
| `valid_overlaps` | string | No | Range literal such as `[2026-06-10,2026-07-27)`, `(,2026-07-27]`, `[2026-06-10,)`. Mutually exclusive with `valid_at`. Aliases: `overlaps`, `valid_during` |
| `time_kind` | string | No | `effective`, `valid`, `occurred`, `due`, or `mentioned`. Narrows valid-time matching to one kind; usable on its own. Alias: `kind` |
| `compact` | boolean | No | Default `false`. Omit note bodies and matched excerpts; keep identifiers, metadata, relation targets, scores, and pagination |
| `search_all_projects` | boolean | No | Default `false`. Search every accessible project and workspace. Ignored when `project` or `project_id` is given |
| `projects` | list[string] | No | Search a chosen subset of projects by name (as `list_memory_projects` reports it) or external id. An unknown name is an error. Ignored when `project` or `project_id` is given |

The `search_type` parameter controls the search strategy. `hybrid` is the default — it combines keyword and semantic search. `text` is keyword-only. `vector` and `semantic` are equivalent — pure meaning-based similarity. See [Semantic Search](/concepts/semantic-search) for details on each mode.

::note
**Semantic search is always on in v0.24.** The `semantic_search_enabled` setting is removed and ignored if present. On hosts where the vector runtime cannot load (for example python.org Python on macOS), search falls back to keyword-only and a `vector` or `hybrid` query reports that semantic search is unavailable. See [Upgrade to v0.24](/whats-new/v0-24-upgrade).
::

**Boolean queries.** A query containing uppercase `AND`, `OR`, or `NOT` without an explicit `search_type` runs as full-text, because the vector half of hybrid search cannot honor them. `NOT` excludes a term found anywhere in the note.

**Cross-project search.** `search_all_projects=true` and `projects=[...]` run one scoped query per database (one for a local install, one per cloud workspace) and rank results across projects together. Every hit on a page spanning projects carries `project` (JSON) or a `- project:` line (text), so follow-up calls can be routed to the right project.

**Valid-time filters** query when a note *says* a claim holds — observation qualifiers like `- [decision] @effective:2026-06-10 The cache layer will use Redis.` — which is a different axis from `after_date` (when the note was indexed). Sources with no temporal qualifier are excluded from any valid-time query, and results default to observations. A malformed filter is refused rather than ignored.

**Result fields.** Search results expose each note's stable `external_id` in JSON and Markdown output. Use it for web-app deep links or exact follow-up operations instead of parsing a title or permalink. Results also carry `content_length` and `content_truncated` so you can tell when a content preview is partial, and metadata values keep their JSON types (numbers, booleans, lists).

#### Metadata filter operators

| Form | Example | Meaning |
|---|---|---|
| Equality | `{"status": "draft"}` | Field equals value |
| Null | `{"owner": null}` | Key absent or explicitly null |
| List | `{"tags": ["security", "oauth"]}` | Array contains all values |
| `$in` | `{"priority": {"$in": ["high", "critical"]}}` | Any of the listed values |
| `$gt` `$gte` `$lt` `$lte` | `{"schema.confidence": {"$gt": 0.7}}` | Comparison |
| `$between` | `{"score": {"$between": [0.3, 0.8]}}` | Inclusive range |
| `$contains` | `{"tags": {"$contains": "security"}}` | Array contains value (or list of values) |
| `$exists` | `{"owner": {"$exists": true}}` | Key has a non-null value |

The leading `$` is optional (`{"started": {"gte": "2026-01-01"}}` works), and several operators on one field AND together: `{"started": {"$gte": "2026-01-01", "$lt": "2026-02-01"}}`. Nested keys use dot notation. An unknown operator's error lists the valid ones. See [Metadata Search](/concepts/metadata-search).

Cloud search projects reviewed notes as clean prose rather than CriticMarkup. JSON note results include `review_summary` counts (`open_comments`, `resolved_comments`, `pending_suggestions`, and `total_pending`). If a stale search fragment splits or exposes review markup during asynchronous index reconciliation, Cloud omits that hit instead of returning ambiguous storage bytes.

Use `categories` for observation categories such as `[decision]`, `[rule]`, or `[follow-up]`. `metadata_filters` only checks note frontmatter, so `metadata_filters={"category": "decision"}` matches a frontmatter field named `category`, not observation categories. The singular `category` is accepted as an alias, and comma-separated strings work (`categories="decision,rule"`). Matching is exact, and categories only exist on observations — explicitly passing `entity_types=["entity"]` alongside `categories` returns nothing.

::note
**Parameter aliases.** `search_notes` accepts `q`, `search`, or `text` as aliases for `query`; `all_projects` for `search_all_projects`; `page_number` for `page`; and `limit` / `per_page` for `page_size`. Search responses also include a result total for pagination.
::

### `build_context`

Build context graph from a memory URL. Traverses the knowledge graph from a starting entity, following relations to a configurable depth.

| Parameter | Type | Required | Notes |
|---|---|---|---|
| `url` | string | Yes | `memory://` URL or path |
| `depth` | string or integer | No | Traversal depth, `1`–`5` (default `1`). Use `2` or `3` for broader context |
| `timeframe` | string | No | Time window filter (default `7d`). Accepts formats like `7d`, `1 week`, `30d`, `3 months` |
| `page` | integer | No | Default `1` |
| `page_size` | integer | No | Default `10` |
| `max_related` | integer | No | Maximum related entities per level (default `10`) |
| `compact` | boolean | No | Default `false`. Omit note bodies and observation lists (the server skips loading observations); keep identifiers, relation targets, and pagination. Use `read_note` for the notes you pick |
| `output_format` | string | No | Default `"json"`. Also accepts `"text"` for human-readable output |

`build_context` resolves `memory://` URLs exactly: by permalink, title, or file path, with no fuzzy matching. A URL that names no note returns nothing, and a title URL that matches more than one note is refused (as `read_note` does) — pass the permalink instead. Since v0.24, compact JSON has no `observations` key.

In text output, relations the primary note does not own name their source, for example `- [[Brewing Notes]] relates_to [[Bean Origins]]`.

**TimeFrame examples:**

| Value | Meaning |
|-------|---------|
| `7d` | Last 7 days |
| `30d` | Last 30 days |
| `1 week` | Last week |
| `3 months` | Last 3 months |
| `1 year` | Last year |

### `recent_activity`

Recent activity in one project or cross-project discovery mode. When no project can be resolved at all (no parameter, no default project), it returns activity across all projects (discovery mode); otherwise it uses the resolved project.

Entity rows include `external_id` so clients can address the exact note returned.

| Parameter | Type | Required | Notes |
|---|---|---|---|
| `type` | string or list[string] | No | Filter by result type: `"entity"`, `"relation"`, `"observation"` |
| `depth` | integer | No | Relation traversal depth for context, `1`–`5` (default `1`) |
| `timeframe` | string | No | Time window (e.g., `7d`, `30d`, `1 week`) |
| `page` | integer | No | Default `1` |
| `page_size` | integer | No | Default `10` |

## Project and filesystem tools

### `list_memory_projects`

List projects and project stats. Returns name, path, default status, note count, external project ID, and sync/workspace metadata for each project. In cloud mode, this discovers projects across **every** accessible workspace, not just the current one — so a team's projects show up without switching workspaces first.

| Parameter | Type | Required | Notes |
|---|---|---|---|
| `output_format` | `"text"` or `"json"` | No | Use `"json"` when an agent needs exact `project_id` values for later tool calls |

### `create_memory_project`

Create a project.

| Parameter | Type | Required | Notes |
|---|---|---|---|
| `project_name` | string | Yes | Name for the new project |
| `project_path` | string | Yes | Filesystem path for the project |
| `set_default` | boolean | No | Default `false`. Set to `true` to make this the default project |
| `workspace` | string | No | Cloud workspace name or slug to create the project in (cloud only) |

### `delete_project`

Remove a project from Basic Memory. Local projects keep their note files by default; cloud projects always have their files deleted.

| Parameter | Type | Required | Notes |
|---|---|---|---|
| `project_name` | string | Yes | Name of the project to remove |
| `delete_notes` | boolean | No | Default `false`. **Local projects only:** set to `true` to also delete the note files from disk. Ignored for cloud projects |
| `workspace` | string | No | Cloud workspace selector (slug preferred; tenant ID or unique name also accepted). Implies cloud routing: without cloud credentials the call fails fast |

::warning
**Cloud deletes always remove files (v0.24).** Deleting a cloud-routed project removes its cloud files whether or not `delete_notes` is set. They can be recovered only from a cloud snapshot (`bm cloud snapshot list`). See [Upgrade to v0.24](/whats-new/v0-24-upgrade).
::

Cloud deletion applies when the MCP session is hosted or routed to cloud, or given a `workspace` selector. Hosted deletion is asynchronous: the tool response reports the project deletion status and background job ID when the cloud backend queues the work. The background job removes indexed and unindexed objects under the exact project prefix before completing the hard delete. Existing snapshots follow their separate retention lifecycle.

### `list_directory`

List directory contents with optional depth, glob filter, and sorting.

| Parameter | Type | Required | Notes |
|---|---|---|---|
| `dir_name` | string | No | Directory path to list (root if omitted) |
| `depth` | integer | No | How many levels deep to list |
| `file_name_glob` | string | No | Glob pattern to filter returned files (e.g., `*.md`, `schemas/*`). Nonmatching directories are still traversed within `depth` |
| `sort` | string | No | Ordering: `title_asc`, `title_desc`, `updated_asc`, or `updated_desc`. Omit for the default filename ordering |
| `page` | integer | No | One-indexed page; default `1` |
| `page_size` | integer | No | Nodes per page; default `10`, maximum `200`. Aliases: `limit`, `per_page` |
| `output_format` | `"text"` or `"json"` | No | JSON includes structured pagination metadata |

Large listings are bounded. Continue with the next `page` instead of assuming one response contains every file. File nodes include `external_id` in both text and JSON output.

Glob filtering applies to returned nodes, not traversal. For example, `depth=2` with `file_name_glob="*.md"` still finds Markdown files inside a folder whose own name does not match `*.md`.

Explicit sorts (v0.23) order folders before files, apply deterministically before pagination, and use note titles for `title_*` modes. Folders have no canonical update timestamp, so `updated_*` modes keep folders name-ascending while still listing them first.

### `list_workspaces`

List available cloud workspaces. Returns workspace names and tenant IDs for the authenticated user.

## POSIX read tools

v0.24 turns on six read-only tools modeled on familiar shell commands: `ls`, `find`, `grep`, `cat`, `tail`, and `man`. They sit alongside the rich tools above and return compact JSON, which makes them cheap for an agent to navigate with. They never write.

::note
The POSIX tools are on by default. Set `enable_posix_tools=false` in config (or `BASIC_MEMORY_ENABLE_POSIX_TOOLS=false`) to hide them; the rich tools (`read_note`, `search_notes`, `list_directory`) cover the same ground.
::

**Projects are mount points.** `ls(path="/")` with no project lists your projects as directories. A path whose first segment names a project routes there, so `ls(path="research/notes")` and `cat(identifier="research/notes/topic.md")` read from the `research` project. The paths these tools return are project-qualified, so you can pass them straight back. An explicit `project` must agree with any path prefix. When more than one project is addressable, an unqualified path is refused instead of silently defaulting, so qualify the path or pass `project` (`grep` and `tail`, which take no path, need `project` in that case).

Every POSIX tool also accepts `project` and `project_id`.

### `ls`

List one directory level.

| Parameter | Type | Required | Notes |
|---|---|---|---|
| `path` | string | No | Default `/`. `/` with no project lists projects; `<project>/path` routes into that project |
| `page` | integer | No | Default `1` |
| `page_size` | integer | No | Default `10`, maximum `200` |

### `find`

Recursively list files by name glob, or query notes by frontmatter metadata.

| Parameter | Type | Required | Notes |
|---|---|---|---|
| `path` | string | No | Default: project root. With `meta`, scopes results to this subtree |
| `name` | string | No | File-name glob such as `*.md`. Cannot combine with `meta` |
| `depth` | integer | No | Levels to recurse, `1`–`10` (default `10`). Cannot change alongside `meta` |
| `meta` | list[string] | No | Metadata predicates that must all hold (see below) |
| `fields` | list[string] | No | Frontmatter fields to return per hit (dot-paths allowed). Requires `meta`; replaces the note body with the note's identity plus these values |
| `page` | integer | No | Default `1` |
| `page_size` | integer | No | Default `10` |

Predicate forms: `status=active` (equality), `confidence>0.6` (also `>=`, `<`, `<=`), `priority in high,critical`, `tags has security,oauth` (array contains all), `score between 0.3,0.8` (inclusive), `owner=null` (missing or null). Keys accept dot-paths, and `note_type` aliases the frontmatter `type` key. Quote a value to force a literal string (`status="true"`).

```text
find(path="research", meta=["status=active", "confidence>0.6"], fields=["title", "priority"])
```

### `grep`

Search note content in one project. `pattern` is matched as full-text keywords, not a regex, and a pattern found in no note returns no results.

| Parameter | Type | Required | Notes |
|---|---|---|---|
| `pattern` | string | Yes | Text to search for |
| `semantic` | boolean | No | Default `false`. Rank by meaning (hybrid semantic plus full-text) instead of keywords. Cannot combine with `context_lines` |
| `context_lines` | integer | No | `0`–`10`. Return case-insensitive matching lines with surrounding context and line numbers, merged into windows, instead of whole notes |
| `max_matches` | integer | No | Default `10` (`1`–`100`). Matching lines shown per note; requires `context_lines` |
| `page` | integer | No | Default `1` |
| `page_size` | integer | No | Default `10` (maximum `100` with `context_lines`) |

When a note has more matches than `max_matches`, the result carries `next_match_line` for a targeted `cat` or `read_note` range read.

### `cat`

Print a note's content, optionally sliced. Returns the `read_note` JSON payload, including `checksum`.

| Parameter | Type | Required | Notes |
|---|---|---|---|
| `identifier` | string | Yes | Title, permalink, `memory://` URL, or `<project>/path` (resolved exactly) |
| `start_line` | integer | No | First line (1-based, inclusive) |
| `end_line` | integer | No | Last line (inclusive) |
| `section` | string | No | Heading to read: `Decisions`, path form `Auth/Decisions` to disambiguate, or `Heading[1]` for the second duplicate. Cannot combine with `start_line` / `end_line` |
| `max_tokens` | integer | No | Approximate token budget. Longer content is cut at a section or paragraph boundary; the response carries `truncated` and `continue_line` |
| `include_frontmatter` | boolean | No | Default `true` |

```text
cat(identifier="research/specs/auth.md", section="Decisions")
cat(identifier="research/specs/auth.md", max_tokens=800)
```

### `tail`

Show the most recently changed notes in a project, newest first. Rows carry `type`, `title`, `permalink`, `file_path`, `created_at`, and `updated_at`.

| Parameter | Type | Required | Notes |
|---|---|---|---|
| `timeframe` | string | No | Default `7d`. Accepts `yesterday`, `2 days ago`, and similar |
| `lines` | integer | No | Default `10`, maximum `100` |

### `man`

Read the Basic Memory manual: one page per MCP tool, with verified examples and gotchas.

| Parameter | Type | Required | Notes |
|---|---|---|---|
| `page` | string | No | Page reference. Any common spelling works: `search-notes(3)`, `3/search-notes`, `search_notes` |
| `query` | string | No | Search the manual. Mutually exclusive with `page`; needs a `manual` project |

With no arguments, `man` returns the manual index. The same pages are MCP resources (see below) and print from the CLI with `bm man <topic>`.

## MCP resources

Basic Memory also answers the standard MCP `resources/read` request, so clients that browse resources can read notes and the manual without a tool call.

| URI | Returns |
|---|---|
| `memory://<project>/<path>` | A note's raw Markdown, frontmatter included. The path can be a permalink, title, or file path. Unknown notes point at `search_notes`; binary files point at `read_content` |
| `memory://man` | The manual index |
| `memory://man/<page>` | One manual page, for example `memory://man/search-notes(3)`. Every page is also listed in `resources/list` with its summary |
| `memory://<workspace>/<project>/info` | Project info as JSON |
| `memory://ai_assistant_guide` | A condensed guide to using Basic Memory well |

Every `memory://` URL Basic Memory hands out in tool results is readable this way. See [Memory URLs](/concepts/memory-urls).

### `basic_memory_diagnostics`

Return a read-only Markdown report for support and installation troubleshooting. It takes no parameters and includes:

## ChatGPT compatibility tools

These are compatibility wrappers for ChatGPT's MCP implementation, which uses a simplified two-tool interface by default. v0.23 gates them by MCP client identity: only OpenAI clients can call them.

- **`search(query)`** — Search across the knowledge base. Equivalent to `search_notes` with default parameters.
- **`fetch(id)`** — Retrieve full document content by permalink. Equivalent to `read_note`.

Non-OpenAI MCP clients receive a clear rejection and must call `search_notes` and `read_note` directly.

See the [ChatGPT integration guide](/integrations/chatgpt) for usage details and limitations.
